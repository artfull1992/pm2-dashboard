# Уточнення до ТЗ v1 · Design reference 1.0

Початкове ТЗ збережене без змін у `reference/`. Ці рішення уточнюють запропонований дизайн; вони не дозволяють змінювати безпеку чи backend-контракти.

1. У всіх макетах 23 синтетичних процеси. Звичайний стан: 20 працюють, 3 зупинені. Offline/stale стосується всіх процесів відповідного сервера, а не лише вибраного. Лічильники перераховуються; невідомі не зараховуються до працюючих. На production доступність таких підсумків перевірити з API.
2. Для stopped/error CPU/RAM/uptime — «—». Для offline/stale у списку — «—», а в деталях дозволені останні відомі значення тільки з явним підписом «дані застарілі». «Агент онлайн» не означає актуальний PM2. Offline не називати статусом самого процесу.
3. У APP-07 керування недоступне в демонстраційній політиці. Остаточна доступність при stale визначається чинним брокером після перевірки Codex; не змінювати політику через макет. APP-04 демонструє дозволений start; це не універсальне правило для всіх stopped-процесів.
4. No access означає право перегляду метрик без права команд. Це не демонстрація повної заборони ресурсу. Стан 403 для всього ресурсу повинен приховувати його дані відповідно до чинної політики. Доступ до логів також перевіряється окремо.
5. Список: 56 px на 1440 px; 48 px на компактному desktop 1280–1400 px. Приховані на mobile CPU та uptime лишаються в деталях; список містить назву/сервер, стан, RAM. Header компактніший на малих екранах.
6. Початково немає вибраного застосунку. Перше відкриття — вкладка Огляд; APP-01 показує вже відкриті користувачем Логи. Вибір зберігає вкладку при наступному перемиканні відповідно до ТЗ.
7. Метрики винесені в заголовок правої панелі й не дублюються у її вкладці Огляд. Імена та стабільні ключі в production походять із чинного контракту. PM2 id=7 у fixture — локальний номер, не ключ вибору.
8. Межа #2D3949 декоративна. Для контурів інтерактивних полів/кнопок — #8293AA, focus — #729BFF. Це уточнює вимогу контрасту значущих контролів, не змінюючи основну палітру.
9. Логи в offline — раніше отриманий кеш тільки якщо він реально існує. При відсутності кешу показати недоступність замість штучного тексту. Помилка мережі APP-12 показує раніше отримані рядки з явним часом; вони не стають новим успішним результатом.
10. Точний час фіксований у fixture. Дані PM2 зібрано 10:21:44; журнал отримано 10:22:02; файл змінено 10:21:58. Для offline/stale час кешу та останнього збору відокремлені. Поле «Зібрано» в огляді — тільки збір PM2, не heartbeat.
11. Статичні кнопки в еталоні не працюють. Поведінку підтвердження та результати команд реалізовувати за чинним механізмом, не за відсутністю modal на PNG. Метрики не доводять успіх команди.
12. Сортування, стабільність позиції при polling та прямі посилання перевіряються на коді. Макет фіксує порядок для порівняння, а не наказує переставляти живі рядки кожні 5 секунд.

13. На mobile-екрані деталей приховані глобальні заголовок/фільтри списку: вони повертаються через «До списку застосунків» зі збереженими значеннями. Це звільняє висоту для журналу.
