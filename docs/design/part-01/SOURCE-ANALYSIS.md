# Аналіз джерел та припущення

Використано наявні в поточній розмові ТЗ v1 і пакет APP-01…APP-16 / DS-01: прочитані ТЗ, README, SPEC-ADDENDUM, QA та вихідні макети, візуально оглянуто DS-01. Новий доступ до production або репозиторію для цієї частини не використовувався.

Підтверджено матеріалами: темний напрям, split-view Applications, компактні підсумки, акцент на актуальності, обмежені логи, зовнішній системний моніторинг, чинні права/брокер як джерело доступності, окремі історія дій і аудит.

Конфлікти з новим завданням вирішено на користь нового завдання: назва тільки Node Control; усі нові fixtures нейтральні; дві теми обов’язкові; спостерігач без логів/керування. У базовому пакеті світлої палітри немає — вона пропонується вперше й не вважається схваленою DS-01.

Немає API-схем, server-side можливостей search/filter, повного enum доставки, гарантованого trigger snapshot та display name ініціатора. Тому всі залежності зведені до SPEC §10 із варіантом без нових API. Fixture не є обіцянкою backend. Приклад показує ID користувача замість вигаданого обов’язкового імені.

Актуальні screenshots відрев’юваних Огляду/Серверів/Деталей сервера не надані в цій поставці. Для частини H потрібно отримати їх; не підміняти актуальний стан старим аудитом і не перепроєктовувати реалізоване без порівняння.

Існуючі ID APP/DS лишилися незмінними, їх файли не входять у новий архів і не перезаписуються. Цей пакет має незалежний namespace NTF/AUD та каталог варіантів.
