# Node Control · Частина 1: Сповіщення та аудит

Версія 1.0 · 23.10.2026 · статус: **пропозиція для погодження**.

## 1. Джерела, рішення та межі

Прочитані матеріали попереднього дизайн-пакета цієї розмови: чинне ТЗ v1, README, уточнення, QA, вихідний HTML/CSS, DS-01. Візуальна основа — APP-01…APP-16 і DS-01: темні поверхні, синій акцент, шрифт 14/20, допоміжний 12/18, відступи 4/8/12/16/24/32, радіуси 6–8. Ідентифікатори й файли APP/DS не змінені. Попередні згенеровані концепти не є еталоном точних значень.

Нові макети використовують тільки Node Control і синтетичні дані. Без інфраструктурних адрес, email, секретів, сирих payload та журналів production. Репозиторій і production-код не змінюються. Локальний прототип — окремий матеріал дизайну без API.

Частини 2–5 не виконуються до погодження частини 1. Для частини H потрібні актуальні screenshots: поточні зображення після реалізації в наявних матеріалах відсутні. Старий браузерний огляд не є підтвердженням відповідності вже відрев’юваних сторінок.

## 3. NTF: структура та семантика

На сторінці вкладки «Активні проблеми» й «Історія», пошук та компактні фільтри. Угорі немає редактора порогів чи інтеграцій: лише перехід «Налаштування» для адміністратора. На mobile доступний через навігацію. Показані лічильники позначають отриману вибірку, а не всі відомі backend записи без підтвердженого total.

Desktop: таблиця з типом/станом проблеми, сервером/застосунком, останнім показником, початком, останнім спостереженням або закриттям, доставкою. Довга назва застосунку в один рядок, повне значення у деталях і доступному title/focus-представленні. Для проблеми сервера застосунок «—» — не вигаданий процес.

Три незалежні поняття:

1. Проблема: активна або закрита; severity — попередження або критично. Наявність інциденту за даними рушія не доводить неочікуваність stopped.
2. Процес: online/stopped/errored або останній відомий/невідомо. У деталях із часом джерела, лише якщо стан реально наданий.
3. Доставка: у черзі / надіслано / помилка / не надсилалось / невідомо, з фактичної моделі доставки. «Надіслано» не означає, що людина прочитала повідомлення, а «помилка» доставки не означає падіння процесу.

Історія показує останній/закривальний показник із підписом. «0 рестартів» — справжній нуль на той момент, не втрачене значення, що спричинило інцидент. Значення при відкритті відсутнє → «—» та коротке пояснення. Закриття через зникнення процесу не позначати «Відновлено» без підтвердження. Причину закриття відображати, якщо є, інакше «Не передано».

Деталі NTF-03 — modal drawer шириною 540 px на desktop, 520 px на tablet; на mobile окрема повноекранна modal-панель. Причина: список зберігає контекст, деталі мають достатньо вертикального місця, навігація між сторінками не потрібна. Заголовок/закриття й footer доступні незалежно від прокрутки середини. Це перегляд, не форма змін; підтвердження закриття не потрібне.

NTF-04: відсутні активні проблеми за успішною перевіркою, а не загальне «все здорове». NTF-05: loading без підстановки старих проблем як актуальних. NTF-06: запит не вдався, стан невідомий, явний повтор. NTF-07: наявна попередня вибірка, одне помітне попередження зі свіжістю; не повторювати довгі пояснення в кожному рядку. Стан доставки теж історичний відносно моменту отримання.

## 4. AUD: таблиця та деталі

Щільний основний рядок: час → ініціатор → дія → ціль/контекст → результат. Від нових до старих за timestamp, не рядковим сортуванням локальної дати. На відміну від NTF, немає друга таблиця з повторенням UUID запиту в кожному рядку.

Людська назва дії — словник до фактичного event type. Невідомий код показувати текстом без вигаданої локалізації. Ініціатор у fixture — «Користувач u-01»: підходить за відсутності display name/email. Дані ініціатора не домислюються, видалений/невідомий користувач відрізняється від системної події. Системного ініціатора показувати лише коли модель його підтверджує.

Деталі AUD-02: результат, час із роком і локальною зоною застосунку, ініціатор, ціль, контекст; technical disclosure — фактичні type/user/request/event ID, якщо є. Немає великих JSON або «показати секрет». Успіх керуючої дії не дорівнює поточному здоровому стану процесу.

Пошук, тип дії й результат у макеті явно обмежені завантаженою вибіркою: це fallback без нового search endpoint. «Показати старіші» лишається чинною cursor/load-more поведінкою. За підтвердженого серверного пошуку можна прибрати пояснення обмеження й застосовувати фільтри глобально, зберігши backend pagination. Без такого підтвердження не створювати враження повного пошуку за весь період.

AUD-03: порожній результат пошуку, не відсутність подій назавжди. AUD-04: loading. AUD-05: помилка запиту без вигаданої порожньої історії.

## 5. Ролі й дані

Макети показують адміністратора. У production оператор/спостерігач бачить тільки дозволені сервери та застосунки, якщо розділ доступний їхній ролі. Для аудиту перевірити чинну політику доступності — не розширювати її через макет.

Спостерігач не має доступу до логів і команд, оператор має в межах дозволів. У NTF/AUD немає нового shortcut, що обходить це обмеження. Якщо додавати перехід до контексту застосунку, він не завантажує логи автоматично для спостерігача. Повністю недоступний ресурс не розкриває назву/метрики через загальний лічильник, пошук, список, історію, drawer чи пряме посилання.

Немає прав і тимчасово недоступна операція — різні повідомлення. У цій частині тільки читання; заборонений розділ не зображується як мережева помилка. Дані на клієнті не замінюють серверну авторизацію.

## 6. Фільтри, пагінація та переходи

- Оновлення не стирає поточні фільтри, вкладку, page/cursor або позицію читання.
- При зміні фільтра скинути cursor лише якщо це вимагає чинний backend контракт; не залишати несумісний cursor. Повернення з деталей зберігає повний контекст.
- Не передавати в URL payload або секрети. Стабільний ID проблеми/події брати з контракту, не з імені процесу чи позиції масиву.
- Без total показати кількість отриманих, не вигадувати загальну кількість сторінок. Disabled «Назад/Новіші» лише за фактичної відсутності попередньої вибірки.
- Скидання очищає фільтри; не змінює права. У локальному прототипі це відкриває базовий зафіксований fixture.
- При перегляді попередньої вибірки нові події не вставляються поверх курсора й не зсувають поточний рядок. Політику refresh звірити з реалізацією.

## 7. Адаптивність

1440×900: навігація 184 px, таблиця на всю доступну ширину, 36 px поля/кнопки, NTF рядки 72 px для двох підписів; AUD 56 px. На compact 1366×768 NTF 64 px, AUD 48 px. Це свідоме локальне розширення DS: NTF містить більше незалежних значень, ніж APP-рядок.

1024×768: вузька навігація, поля можуть переходити в два рядки; таблиці лишаються таблицями. Доступ до профілю й виходу лишається внизу навігації. Drawer 520 px із прокручуваною серединою.

390×844: ті самі записи представлені вертикальним списком компактних записів: тип/стан, сервер/застосунок, показник, обидва часові значення, доставка. Для аудиту: дія/результат, ціль/контекст, ініціатор, час. Немає прихованої критичної операції за горизонтальним scroll. Пагінація закріплена внизу панелі, список має власний scroll. Деталі — full-screen; кнопка закриття доступна вгорі та внизу.

На вузькому екрані «Меню» відкриває modal-навігацію зі всіма дозволеними пунктами, профілем і виходом. Доступ до виходу не залежить від висоти сторінки: menu має власну прокрутку. Немає окремого примусового виходу через цей прототип.

200%: приймання на реальному browser zoom, перехід до одноколонкового/послідовного компонування за ефективним CSS viewport. PNG zoom200-reflow демонструє 720×450 CSS px (еквівалент області 1440×900 при 200%), а не доказ роботи браузерного zoom. Контент панелі й меню прокручується; заголовок/закриття/footer доступні. Текст не масштабується CSS transform.

## 8. Accessibility та keyboard

Семантичні table/th для desktop, article для mobile, підписані поля. Відкриття деталей — справжня кнопка, Enter/Space. Tab/Shift+Tab послідовно проходить навігацію, вкладки, пошук, фільтри, доступні рядки й пагінацію. Enter не виконує неочікуваної команди керування.

Modal: фокус на «Закрити», фон inert, Tab утримується всередині; Escape закриває, фокус повертається до конкретного виклику. При прямому відкритті деталей без виклику — fallback на заголовок сторінки/відповідний рядок, не document body. Натискання scrim не закриває випадково; Escape і дві кнопки є явними шляхами. Візуальний focus — 2 px accent, відступ 3 px; зразки focus PNG включені.

Стан — текст плюс маркер. Невідоме «—» не перетворювати на 0. Loading/error мають коротке доступне оголошення, не повторюване кожним рядком. Іконки навігації у прототипі умовні локальні знаки; у реалізації використати чинний набір.

Touch target ≥44×44 px у mobile, включно з відкриттям запису, меню, закриттям та пагінацією; compact desktop controls 36 px. Контраст тексту ≥4.5:1, важливих меж ≥3:1. Декоративні роздільники не є єдиним способом знайти control.

## 10. Перевірка API та fallback без нових даних

| Потреба | Що перевірити | Fallback |
|---|---|---|
| Фільтри NTF/AUD | Чи є server-side search/filter, scope, total | Позначений пошук тільки в отриманій вибірці |
| Поля події | Фактичні type, actor, target, outcome, request ID | Невідомий код/ID, «—» для відсутнього; не синтезувати |
| Контекст сервера у події | Чи наданий і дозволений він | «Контекст не передано»; не вгадувати по PM2 id |
| Severity і lifecycle | Чинні enum і причина закриття | Тип проблеми та сире підтримуване значення без вигаданого recovery |
| Значення при відкритті | Чи є snapshot trigger value | «— · не передано», залишити останній показник із часом |
| Поточний стан процесу | Чи є коректна прив’язка/час PM2 | «Не отримано», без додаткового endpoint |
| Доставка Slack | Один результат чи кілька спроб, mapping enum | «Невідомо/не передано», не обчислювати «доставлено» з відсутності помилок |
| Свіжість списку | Server timestamp/check timestamp | «Отримано клієнтом о …», не називати це часом перевірки |
| Сортування/історія | Курсор, порядок timestamp, timezone | Чинний маршрут/курсор, обмеження явно підписати |
| Права розділу | Чи доступний audit конкретній ролі | Зберегти поточну авторизацію, не додавати доступ |

Типи command.restart/auth.login у fixture — умовні приклади словника, не нові обов’язкові event codes. Ні approval/acknowledge, ні закриття/видалення інцидентів, ні повтор доставки з цієї сторінки не додаються.

## 11. Acceptance criteria для реалізації та незалежного review

1. Відтворити NTF-01…07, AUD-01…05 з таблиці відповідності у двох темах. Скріншоти при тих самих viewport, DPR 1, фіксованому часі та синтетичних fixtures. Порівнювати геометрію, не антиаліасинг іншого системного шрифту.
2. Перевірити 100–500+ записів/історичних подій: тільки чинна пагінація/завантаження, без запитів для кожного рядка; довгі імена не ламають сітку. Не додається вимога вантажити все в клієнт.
3. Stopped не оголошується несподіваною аварією; проблема, процес і доставка не зливаються в один статус. Закрито без підтвердження відновлення не дорівнює healthy.
4. Застарілий стан не виглядає поточним; помилка запиту не показує «активних проблем немає». Невідомий actor/metric/delivery не перетворюється на правдоподібне значення.
5. Зберігаються фільтри, дозволений scope, cursor і scroll при відкритті/закритті деталей та refresh. Старі відповіді не підмінюють новий вибір.
6. Аудит відсортований за timestamp; 13.10 не стоїть перед 23.10 через рядкове сортування чи додавання нової пачки. Події без target/context відображають чесний fallback.
7. В drawer і таблиці немає webhook, токенів, cookie, паролів, невідфільтрованого JSON. Немає шляху до заборонених логів/ресурсів через деталі або пряме посилання.
8. Mobile/tablet/compact та 200% zoom: немає page-level горизонтального overflow, критичні кнопки й вихід доступні; довгі списки й деталі мають контрольований scroll.
9. Перевірити Tab/Shift+Tab/Enter/Space/Escape, focus trap і return focus, screen reader назви таблиць/кнопок/полів. Тільки видимі елементи потрапляють у tab order.
10. Виміряти контраст тем, focus і touch targets. Тема не змінює severity, щільність, доступ чи дані.
11. Чинні lint/typecheck/unit/integration/e2e виконати за правилами репозиторію під час реалізації. Локальна перевірка макетів не є тестом backend або прав.
12. Уточнення API та спільних компонентів передати на рев’ю Codex; production реалізує Claude окремим погодженим кроком. Нові можливості backend не вводити мовчки.

## 12. Статус погодження

Погоджений раніше загальний напрям: темна тема та компактний робочий інтерфейс. Усі NTF/AUD, світла тема й нові патерни цього пакета — на погодження. Після рішення користувача зафіксувати схвалені ID/теми/варіанти у каталозі; до цього не називати їх approved. Частини 2–5 не об’єднуються з цією поставкою.
