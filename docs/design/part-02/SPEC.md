## Джерела та спадкоємність

Використані ТЗ v1, APP-01…16 / DS-01 та доступні вихідні компоненти й специфікація частини 1. Збережені темні токени DS-01, світла палітра-пропозиція частини 1, 14/20 та 12/18 px, крок відступів 4/8/12/16/24/32, контролі 36–40 px desktop, touch ≥44 px. APP/DS/NTF/AUD не перезаписуються і не отримують автоматично новий статус погодження. Перехід до частини 2 прямо доручений користувачем.

Використовується тільки назва Node Control. Сервери, сервіси та облікові записи синтетичні. Адреси example.invalid навмисно не є реальною поштою. Паролі й секрети у fixture не зберігаються, листи або API-запити не надсилаються.

## Користувачі

Таблиця: email, роль, доступ, активність, дії. Email не розбивається посимвольно: один рядок із truncation, повне значення доступне в деталях/title та при фокусі. Не додавати ім’я, avatar, останній вхід або інші відсутні API поля. Статуси мають текст, не лише колір. Лічильник «завантажені користувачі» не видається за backend total.

Пошук у макеті обмежений поточною вибіркою. Чинний серверний пошук/фільтри/пагінацію зберегти, якщо вони є; не замінювати їх локальним пошуком мовчки. Поточна сторінка й фільтри залишаються після закриття меню/форми та повернення з ACL.

Меню дій — overlay, а не додатковий рядок таблиці. «Роль і активність» та «Сервери та сервіси» розділені. Немає самовільно доданого видалення, скидання чужого пароля, інвайту або impersonation. Escape закриває меню й повертає фокус; стрілки переміщують фокус пунктами; поза таблицею меню не обрізається scroll-контейнером у реалізації (portal/top layer). На mobile меню відкривається в межах viewport.

Створення — drawer 540 px, на mobile повний екран. Поля-пропозиція за відомим контекстом: email, початковий пароль, роль, активність. **Точний create payload і можливість задавати початковий пароль перевірити в репозиторії**. Якщо чинний backend видає пароль сам або використовує інший потік, прибрати це поле та зберегти чинний контракт; не будувати invite/email flow. Межі довжини, вимоги пароля та дозволені символи беруться тільки з реалізації. На макеті вимоги не вигадані.

Редагування — email лише для контексту, без пропозиції його змінювати. Можна змінити роль та active, якщо дозволено поточною політикою. Оператор: керування та логи в дозволеному scope. Спостерігач: перегляд без логів/команд. Адміністратор: повний доступ, ACL не обмежує адміністратора.

Для власного адміністративного запису роль і active недоступні; одне пояснення в USR-08. Не додавати обхід через ACL, прямий URL чи альтернативне меню. Інші чинні захисти (останній адміністратор, зміна ролі активного користувача тощо) перевірити й зберегти, не припускати їх відсутність.

Валідація: помилка біля поля з aria-invalid/aria-describedby, summary за потреби; серверна помилка не стирає введені значення. Під час збереження поля й повторний submit заблоковані. Закриття drawer під час pending не означає скасування запиту: реалізація має зберігати й відображати результат, а не показувати успіх до відповіді. У fixture X лишається доступним; це потребує узгодження з чинною моделлю pending. Пароль не відновлювати з локального сховища й не записувати в аудит.

## Чому ACL — окрема сторінка

Редактор може містити багато серверів та 100–500+ сервісів. Маленька modal створює вкладені scroll, ховає контекст користувача й кнопки. Окрема сторінка має власний стабільний URL за фактичним user ID, breadcrumb назад, контекст користувача й закріплену панель дій. Немає modal focus trap для самої сторінки. Невеликі підтвердження й вибір сервера можуть бути modal.

Desktop: сервери 260 px ліворуч, редактор вибраного сервера праворуч. У кожного сервера незалежна чернетка `all` або `selected` плюс стабільні service IDs. UI не використовує назву або PM2 id як глобальний ключ. На tablet ліва панель 220 px. На mobile сервери — горизонтальна компактна смуга з назвами й scope, редактор нижче, нижня панель кнопок не зникає; сторінка й список сервісів мають обмежену прокрутку.

«Додати сервер» відкриває компактний вибір із пошуком тільки серед доступних для призначення серверів. Уже призначені не дублюються. Новий сервер за замовчуванням має selected і 0 вибраних, ніколи all. До явного вибору не надавати доступ автоматично. У реалізації можливі два безпечні варіанти: не дозволяти збереження selected=0 або зберігати як відсутність grant, якщо це чинна семантика API. Макет використовує перший варіант.

Режими:

- **Усі сервіси — поточні й майбутні**: одна явна політика, не snapshot поточного списку. Присутній підпис про майбутні сервіси. Перемикання є розширенням доступу, що набуває чинності лише після збереження.
- **Вибрані сервіси**: тільки конкретні service IDs; не всі поточні автоматично. Сервіси, додані пізніше, не отримують доступ. Чернетку попереднього selected-вибору можна зберігати під час перемикання режиму; фактичний payload має містити один режим.

Checkbox/radio мають власний розмір 16 px, не ширину всього контейнера. Label є великою клікабельною областю; на mobile рядок не нижчий 48 px. Довга назва в один рядок; повне значення доступне для читання без візуального розбиття.

Пошук фільтрує представлення і не змінює selected set. Лічильник показує загальну кількість вибраних у scope сервера, включно з прихованими пошуком. Не додавати неочевидне «вибрати все», яке може означати всі збіги/сторінки. Пошук без збігів не дорівнює відсутності сервісів чи grants. Якщо backend пагінує, зберігати selected IDs між сторінками та явно позначати обсяг пошуку.

Видалення сервера змінює лише чернетку, не миттєво відкликає реальний доступ. Confirmation називає сервер і пояснює необхідність збереження. Перемикання між серверами не втрачає їх незалежний вибір. Якщо прибрали останній — редактор показує відсутність доступів як чернетку, Save лишається можливим для явного відкликання всіх grants.

Незбережені зміни: індикатор унизу, Save увімкнений лише за валідної відмінності від baseline. Скасування/вихід/Back із dirty відкриває ACL-12. Рух між серверами чи пошук не запускає це підтвердження, бо не втрачає чернетку. Успішне збереження оновлює baseline й прибирає dirty. Не трактувати тимчасове завантаження як порожній список.

Помилки: при initial load error Save недоступний; попередню модель не можна заміняти порожнім ACL. При save error чернетка лишається, видиме повідомлення над редактором; при timeout результат може бути невідомий — спочатку перевірити збережений стан, а не сліпо дублювати write. Під час pending редагування й дублювання запиту заблоковані. Не вигадувати optimistic success.

## Доступи та security invariants

ACL редагує адміністратор. Перевірка ролі та дозволів — серверна для кожної операції, не лише прихована кнопка. Спостерігач не читає логи й не керує навіть за `all`; оператор має ці операції тільки на дозволених сервісах. Full admin не обмежується збереженим ACL. Роль і scope — незалежні виміри.

При переході admin → operator/observer перевірити наявність збережених grants за чинною політикою. Не перетворювати full admin на all для всіх серверів автоматично. Якщо grants немає — чесне «доступів немає» й перехід до ACL. Зміна активності не видаляє grants без окремого контракту; неактивний користувач не може ними скористатися. Відкликання активних сесій — за чинною серверною реалізацією, не обіцянкою дизайну.

## Адаптивність і клавіатура

1440×900, 1366×768, 1024×768, 390×844. При 200% — reflow за ефективним CSS viewport, без transform/масштабованих знімків. PNG 720×450 — лише модель такого компонування, не підтвердження реального browser zoom.

Desktop таблиця, mobile компактні записи без втрати меню. На низьких екранах toolbar не виштовхує основні дії: середина прокручується, кнопки доступні. Профіль/вихід доступні у вузькій навігації через «Меню».

Tab/Shift+Tab, Enter/Space; radio підтримує нативні стрілки. Видимий focus 2 px accent з offset 3 px. Меню: ArrowUp/Down, Escape, return focus. Modal: фон inert, фокус усередині, Escape/Close повертає до виклику. Редактор ACL як сторінка не утримує фокус. Dirty page leave і видалення server grant використовують явні підтвердження, Enter не запускає save випадково із service search.

## API-питання та fallback

| Потреба | Що перевірити | Без нового backend |
|---|---|---|
| Create user | Поля, початковий пароль, валідація, повернення ID | Зберегти чинну форму/контракт, прибрати непідтверджене поле |
| User edit | Роль, active, self/last-admin захисти | Read-only для заборонених властивостей; не розширювати API |
| User list | Пагінація, total, глобальний пошук | «У завантажених», чинна сторінка/курсор |
| Server/service pickers | Catalog, pagination, freshness, stable IDs | Поточні доступні списки, чесна область пошуку, selected IDs зберегти |
| Scope all | Як API представляє поточні й майбутні | Тільки чинний all scope; не емулювати список поточних IDs |
| Selected=0 | Чи означає відсутність grant або помилку | Блокувати Save та вимагати вибір/прибрати сервер |
| Partial failure/conflict | Атомарне збереження чи per-server writes, version guard | Не оголошувати all-success; перечитати/показати частковий результат за контрактом |
| Зниклий сервіс | Чи повертає API збережені недоступні IDs | Не скидати grants мовчки через відсутність у поточному catalog |
| Observer | Роль + заборона логів/команд | Зберегти серверну політику, не вводити per-command перемикачі |

Немає делегування, granular start-only/restart-only, invite, SSO, реєстрації або password reset для інших користувачів.

## Відхилення від DS та межі прототипа

Нові компоненти: USR drawer форми, menu overlay, ACL master/detail page і service checklist. Вони використовують наявні токени й не змінюють APP чи DS-01. Світла тема продовжує пропозицію частини 1, не новий runtime setting. Іконки — локальні умовні символи, у production — чинний набір.

Прототип демонструє пошук сервісів, незалежні selected sets, radio mode, dirty індикацію, modal/menu, додавання/прибирання в чернетці. Збереження, створення користувача, account/logout, серверний пошук/пагінація — **демонстраційні контроли без API**. Це не перевірена функціональна реалізація продукту.

## Acceptance criteria

1. Порівняти USR/ACL з PNG у двох темах на зазначених viewport. APP/DS не перезаписані, нових production dependencies тільки заради дизайну немає.
2. Довгі email/імена сервісів не ламають сітку; меню не збільшує рядок і не обрізається контейнером. Checkbox/radio компактні, поля/кнопки узгоджені.
3. Власний admin не змінює роль/active через UI або API; інші чинні захисти збережені. Повний admin не обмежується grants.
4. Для operator/observer незалежно перевірити all/selected на кількох серверах: observer без логів і команд, operator тільки в scope. Нові сервіси доступні лише у режимі all.
5. Пошук/пагінація/зміна сервера не губить вибір; вибране поза фільтром враховується. Однакові PM2 id на різних серверах не змішуються.
6. Новий сервер не отримує all автоматично. selected=0 не перетворюється на all. Прибирання сервера спершу змінює чернетку, save явно застосовує відкликання.
7. Dirty/save/cancel/Back, pending, validation, timeout/conflict/partial failure перевірені. Initial load error не зберігає порожній ACL. Failed save не стирає чернетку.
8. Чинна серверна валідація email/пароля, права й аудит збережені; жодних паролів у localStorage, логах, URL або screenshots реалізації.
9. Keyboard/focus/Escape/touch і реальний zoom 200%, screen reader та low-height перевірені на реалізації. Локальний render не доводить API/security.
10. За правилами repo — обов’язкові lint/typecheck та змістовні тести створення, редагування, ізоляції ACL і регресій перед прийманням. Реалізація — окреме завдання для Claude після рев’ю Codex.
